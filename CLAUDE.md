# Inkpad++

Inkpad++ by Shmilovitz: a native macOS port of upstream (v8.9.8.1). Goal: behave like the
Windows editor the user knows, but as a real Mac app — not Wine (tried, rejected as terrible), not
a loose clone.

**Naming (MAC-78, 2026-10-19):** "upstream" in this repo means the editor Inkpad++ is ported from;
its name appears only in `NOTICE` and the README credits (the user's rule). Never write it, or the old
name, anywhere else. Exceptions: upstream file names (`Notepad_plus.cpp`, `NppCommands.cpp`, …), the
upstream source URL, the `<NotepadPlus>` XML element of its data files, its `-notepadStyleCmdline`
option, and the marked legacy-migration code that cleans up installs of the old name.

## Decisions (agreed with the user on 2026-10-13)

- **UI:** Swift + AppKit. Native menu bar, Cmd shortcuts, dark mode, Finder "Open With".
- **Editor engine:** Scintilla's Cocoa backend (`ScintillaView`) + Lexilla — the same engine
  upstream uses, so editing/folding/multi-caret/column mode/lexers behave identically.
- **Data files reused verbatim from upstream:** `langs.model.xml`, `stylers.model.xml`,
  `themes/*.xml`, `functionList/*.xml`, `autoCompletion/*.xml`. Upstream user themes must import as-is.
- **Logic:** port non-Win32 C++ from `PowerEditor/src` where it is portable (encoding detection,
  search semantics, session/config formats). Rewrite every Win32 UI piece in AppKit.
- **Out of scope:** upstream plugins (Windows DLLs cannot load on macOS).
- **License:** derived from upstream ⇒ GPLv3; credit kept in `NOTICE`. Upstream's name is Don Ho's
  trademark — never brand the app with it; the app is **Inkpad++ by Shmilovitz**.

## Layout

- `vendor/upstream/` — shallow clone of tag `v8.9.8.1` (gitignored, read-only reference).
  - `scintilla/cocoa/` — ScintillaView, `Scintilla/Scintilla.xcodeproj`, `ScintillaTest/` (sample host app)
  - `lexilla/src/Lexilla/Lexilla.xcodeproj`
  - `PowerEditor/src/` — upstream app code (`ScintillaComponent/`, `WinControls/`, `Parameters.cpp`, …)
  - `PowerEditor/src/langs.model.xml`, `stylers.model.xml`; `PowerEditor/installer/{themes,functionList,APIs}`
  - `boostregex/` — upstream's regex engine for Scintilla search (Perl-style regex, used by Find/Replace)
- `scripts/build-deps.sh` — builds `build/deps/Scintilla.framework` + `liblexilla.a` from vendor/.
- `project.yml` — XcodeGen spec (the generated `Inkpad++.xcodeproj` is gitignored).
- `Inkpad/Sources/` — the app (Swift, AppKit, no nibs). `LanguageTable.swift` is generated from
  upstream's `_langNameInfoArray`; regenerate it rather than editing by hand.
- `Inkpad/Resources/Assets.xcassets/AppIcon.appiconset` — app icon PNGs, generated by
  `swift scripts/make-icon.swift` (an original design; never use upstream's chameleon logo).
  Edit the script and regenerate rather than editing the PNGs.
- `Inkpad/Info.plist`'s document types are generated from `langs.model.xml` by `swift scripts/gen-file-types.swift` (MAC-50; `--check` runs in make-pkg.sh). Regenerate rather than editing them.
- Visible app name (MAC-66): `APP_DISPLAY_NAME` in `Config/App.xcconfig` (Inkpad++), written to
  `en.lproj/InfoPlist.strings` by a build phase; UI strings use `AppName.display`. A gitignored
  `Config/Local.xcconfig` could override it for a personal build; the user's own one was removed on
  2026-10-19 (MAC-78) — their Mac runs Inkpad++ too. Info.plist keeps the `.app` file's name: Finder
  shows the localized name only while the two match. MAC-67: `make-pkg.sh` names the installer and
  its title after the built app's name (`scripts/display-name.sh`), so it builds
  `dist/Inkpad++-<v>.pkg`. Debug builds are always "Inkpad++ Debug" (`Config/Debug.xcconfig`): test
  hosts once showed in the Dock under the release name and looked like the user's editor stuck.
- `Themes/Inkpad Light.xml` (MAC-80) — Inkpad's own BBEdit-like default theme (Menlo 12, calm colours,
  soft gutter, no red fold line), generated from upstream's stylers.model.xml by
  `python3 scripts/gen-inkpad-light.py`; regenerate rather than editing. The build copies `Themes/*.xml`
  next to upstream's themes; `ThemeManager.preferredName` is the theme until the user picks one. Defaults
  since MAC-80: triangle folds (MAC-82: BBEdit-sized images, plus a corner on each block's closing line), line spacing +2 px (Settings › Editing); MAC-81: full path in the title.
- At build time a script phase copies `langs.model.xml`, `stylers.model.xml` and `themes/` from
  vendor/ into the app's `Resources/upstream/`.

## Build

```bash
scripts/build-deps.sh && xcodegen && xcodebuild -project Inkpad++.xcodeproj -scheme Inkpad++ -derivedDataPath build/dd-app build
```

App: `build/dd-app/Build/Products/Debug/Inkpad++.app`.

Tests: `xcodebuild test -project Inkpad++.xcodeproj -scheme Inkpad++` (target `Inkpad++Tests`; the
app's module is `Inkpad`, since `Inkpad++` is not a legal Swift module name).

Installer: `scripts/make-pkg.sh` → `dist/Inkpad++-<version>.pkg` (tests, Release build, signing,
then `pkgbuild` + `productbuild`; installs into `/Applications`). A `.pkg` is the project's installer
format — not a `.dmg`. The package declares Inkpad++ **must-close**: if it is running, Installer asks
to close it before installing (MAC-19). Only the newest installer is kept — the script deletes older
`Inkpad++-*.pkg` in the output folder after a successful build (user's rule, 2026-10-13). Note the two identity classes: a Developer ID *Application* certificate signs
the app, a Developer ID *Installer* certificate signs the package.

## Vendor quirks (handled without editing vendor/)

- Lexilla's Xcode project hard-codes signing team 4F446KW87E and omits the three lexers upstream
  adds (`LexObjC`, `LexSearchResult`, `LexUser`), so `build-deps.sh` compiles Lexilla directly.
- `LexUser.cxx` includes `<windows.h>` and calls MSVC `_itoa`: a generated shim header covers both.
- upstream appended an unguarded C++ block (`SearchResultMarkings`, `std::vector`) to the public
  `Scintilla.h`. The Swift bridging header is plain ObjC, so `build-deps.sh` wraps it in
  `#ifdef __cplusplus` in the built framework's copy.
- Scintilla.h and other vendor files use CRLF line endings: patterns must allow `\r?\n`.
- Regex search is upstream's Boost engine (MAC-29): `build-deps.sh` builds `boostregex/` into
  `libscintilla-boostregex.a` and links Scintilla with `SCI_OWNREGEX`. On macOS Boost classifies
  `wchar_t` through the "C" locale, where libc++ knows no non-ASCII letters (`\w` missed Hebrew);
  `scripts/deps/BoostRegexLocale.cxx` (force-loaded) installs a UTF-8 `ctype<wchar_t>` facet globally.
  upstream's extra flags (`SCFIND_REGEXP_DOTMATCHESNL`, …) come from `BoostRegexSearch.h`.

## Testing gotchas

- Never drive the app with `osascript ... keystroke` unless Inkpad++ is verified frontmost: keys go
  to whatever app has focus (on 2026-10-13 a stray `x` + ⌘S reached the user's Chrome). Use
  `key code` (layout-independent; the user's input source is Hebrew, so `keystroke "x"` types ש)
  and check `frontmost` first. `pkill Inkpad++` fails on the `+`; use `pkill -f 'Inkpad\+\+\.app/Contents/MacOS'`.
- A Debug build launched by hand shares the installed app's Recent Files and session (same bundle
  id). For manual checks launch it isolated: `open --env INKPAD_ISOLATED_STORAGE=1 -a <app> <file>`
  (tests are isolated automatically — MAC-23). Never quit or drive the user's own running Inkpad++.
- With two Inkpad++ processes running (same bundle id), System Events' `set frontmost` on the test
  instance can activate the *other* one, and menu clicks then land there (2026-10-14: a test script
  typed into the user's instance). Before any UI scripting, list `pgrep -fl 'Inkpad\+\+\.app/Contents/MacOS'`;
  if anything besides the test instance runs, do not script the UI — ask the user first. After
  activating, check `unix id of (first process whose frontmost is true)` equals the test pid.
- `UserDefaults.removePersistentDomain(forName:)` deletes that domain for the whole user account,
  whichever `UserDefaults` instance is asked. Tests only ever pass a throwaway suite name
  (`app.inkpad.Inkpad.tests.*`), never `app.inkpad.Inkpad` — on 2026-10-14 an uninstaller test did,
  and wiped the installed app's preferences (no backup existed).
- Debug builds use the bundle id `app.inkpad.Inkpad.debug` (Release keeps `app.inkpad.Inkpad`), so
  Finder / Open With never launches a build-folder copy for the user's files and a Debug build never
  reads the installed app's preferences. Before this, one did (2026-10-14).

## Milestones (each one ends with a working app)

1. **Skeleton** — Scintilla + Lexilla building for arm64; one window, open/save, lexer by file
   extension, upstream default theme from `stylers.model.xml`.
2. **Tabs** — multi-document, session restore, recent files, encoding + EOL in status bar.
3. **Find/Replace** — Normal / Extended / Regex (boostregex), Find in Files, Mark, incremental search.
4. **Language menu, Style Configurator, themes, Preferences.**
5. **Edit commands** — line ops, case, comment toggle, Column Editor, macros, Shortcut Mapper.
6. **Panels** — Function List, Document Map, Folder as Workspace, split view.
7. **Packaging** — signed `.app`, `.pkg` installer, file-type associations.

Milestone 1: **done** (2026-10-13). One window per document; open/save (Finder "Open With" too);
lexer + keywords by extension from `langs.model.xml`; default theme from `stylers.model.xml`; folding,
brace match, upstream-style status bar; BOM/UTF-8/UTF-16/ANSI decode + byte-exact save; EOL kept.

Known approximations, to be closed in later milestones:
- Per-language lexer setup (`ScintillaEditView::defineDocType` and its set*Lexer helpers) is the
  table in `LexerRecipes.swift` (MAC-11): keyword sets per language, lexer properties, substyles
  (substyle1…8 = keyword classes 9…16), HTML/PHP/ASP/JSP as "hypertext" with embedded JS/PHP/VBScript
  styles, EOL-filled styles, tabSettings, indent guides, fold margin. Not ported: NFO's Lucida Console
  default and per-language word characters.
- Encoding detection (MAC-10) is upstream's: uchardet (`build/deps/libuchardet.a`, from
  `PowerEditor/src/uchardet`) + EncodingMapper (`CodePageTable.swift`, generated, 46 code pages).
  Differences: valid UTF-8 is accepted before asking uchardet; "ANSI" is Windows-1252 (upstream
  uses the system code page), so detected 1252 / ISO 8859-1 show as ANSI; uchardet's KOI8-R and
  ISO-8859-8-I names are mapped (upstream's table misses them). Converting *to* an arbitrary code
  page (Encoding › Character sets menu) is not built yet.
- Font sizes are scaled by 4/3 (Windows 96 dpi points → macOS points) and new files use LF, not
  CRLF — both now Preferences (MAC-12/MAC-38: Misc. › scale font sizes, New Document › Format).
- First-line detection (`LanguageDetector`, MAC-11) follows upstream's detectLanguageFromTextBeginning.

Milestone 2: **done except MAC-25** (2026-10-14, release 0.1.8) — tabs, session restore, recent files,
encoding/EOL pickers, encoding detection, tail -f, reload on external change, Save as Administrator
with Touch ID, window placement. MAC-25 (full security review incl. the GitHub code) is the stage's
last item by the user's choice.

Privileged helper (MAC-24/MAC-28, hardened in MAC-55/MAC-56): `InkpadHelper` is installed by the `.pkg` —
`scripts/pkg/postinstall` copies it to `/Library/PrivilegedHelperTools/app.inkpad.Inkpad.helper` (root:wheel
0544), writes `/Library/LaunchDaemons/app.inkpad.Inkpad.helper.plist` (with a `SpawnConstraint` on team +
identifier) and the authorization right `app.inkpad.Inkpad.save` (admin, never cached), then bootstraps it.
The app sends an AuthorizationExternalForm with each save; the **helper** asks for the right (SecurityAgent,
Touch ID or password, naming the path) before writing, and refuses startup/security files. Only
Developer ID builds of team 96Y4LX7FVB pass the code-signing requirements, so Debug builds always use the
password path. Tests run the pkg scripts with stub `launchctl`/`security` — never the real ones.

## Process requirements (set by the user on 2026-10-13)

- **Jira:** every item of work gets a ticket in project **MAC** ("inkpad++") on the private
  Atlassian site — board https://nachum-shmilovitz.atlassian.net/jira/software/projects/MAC/boards/167.
  Open the ticket before the work starts, close it with a description of what actually shipped.
- **Testing:** every feature ships with full unit-test coverage; every bug fix ships with a
  regression test. Extract logic out of AppKit views where needed so it can be tested headless.
- **Versioning:** the line started at `0.1.0`; the user set it to **`1.0.0`** and then **`1.1.0`** on
  2026-10-18 (`MARKETING_VERSION` in `project.yml`; MAC-71). Every release still bumps the **patch** only
  (1.1.1, 1.1.2, …). When the user sets a version, the next deploy patch releases that version as is.
- **`deploy patch`** means, in order: run the unit tests (a failure stops everything) → bump the
  patch → update and close the Jira tickets → commit and push → build the `.pkg` installers into `dist/`
  for every requested platform (currently macOS arm64 only; `.pkg`, never `.dmg`): `Inkpad++-<v>.pkg`
  (a second, public package is built only when a personal name override exists, MAC-75) →
  publish **`Inkpad++-<v>.pkg`** as GitHub release `v<version>` with
  `scripts/github-release.sh dist/Inkpad++-<v>.pkg <version>`, which writes the notes from the commits
  since the previous release and deletes every older release so only the newest one stays (MAC-68,
  user's rule 2026-10-18; tags stay) → ask the user whether to install it.
- **Installing** (when the user says yes): it needs their admin password / Touch ID, so open the `.pkg`
  in Installer (`open dist/Inkpad++-<v>.pkg`) for them to confirm — never try `sudo installer`. If
  Inkpad++ is running, **ask the user whether to close it** first (it may hold unsaved work); the
  package's must-close prompt asks again in Installer. Never quit it unasked.
